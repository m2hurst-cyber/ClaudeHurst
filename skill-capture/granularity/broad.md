# Writing skills at BROAD granularity

You are writing for a firm that collects **deliverables** — a complete piece of work,
carried from its inputs to the thing that gets handed on.

## Size and shape

- **3–9 steps.**
- **Body under 350 lines.** Use `## Steps` with named phases where that helps a reader
  navigate; keep the numbered list underneath.
- One deliverable that leaves the team.

## What counts as a skill here

Could you point at the output and say "that is what this produces"? A valuation note, a
close pack, a K-1 set, a board deck.

Prefer the **fuller procedure**. Where a part of it could stand alone but is nearly always
done as part of this, keep it together and mention in `## Steps` that it can be run on its
own.

- Good: *produce the quarterly valuation note for a covered name*.
- Good: *prepare and circulate the month-end close pack*.
- Bad: *unlever the comp betas*. Real, but at this level it is a step inside a deliverable,
  not a skill.

## Steps that belong to a neighbour

Absorb them. At this level the risk is fragmentation, not bloat. Split only where the work
genuinely stops — a different person owns the next part, or it waits on something external.

Where you absorb something that is worth naming, make it a named phase in the steps so it
can still be found.

## Naming

Name the deliverable itself, and say in the description which steps it covers end to end,
so nobody writes a second skill for a part of it.

## Save, extend or branch

- **Save** for a deliverable the library does not yet produce.
- **Extend** readily: at this size, a step someone keeps adding is usually a genuine gap.
- **Branch** sparingly. Two large near-identical skills are a maintenance problem; prefer
  one skill with a documented decision point unless the methods really diverge.

## Worked example

Observed: `pull comps → unlever → relever → discount row → discount FCF → sensitivity grid
→ write note → build exhibits`.

At this level that is **one skill**: *producing a valuation note*. Inside it, name the
phases — WACC, discounting, sensitivity, write-up, exhibits — so a reader can find the part
they need without the library carrying five separate entries for one job.
