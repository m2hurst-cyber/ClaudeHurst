A flow is a sequence of tasks that can cross applications, agents and people: collect the
data, clean it, run the regression, chart it, label the trends, write the paper, build the
deck, append the exhibits.

## Building one

Drag tasks onto the map in the order they must happen. Each task carries who or what runs
it — a model, a macro, or a person — and what it needs before it can start.

- **Reorder** by dragging. **Delete** with the task's menu. **Insert a pause** where someone
  has to look at it before the next step.
- The map shows which task is **running now**, and a task can be deployed mid-sequence
  without restarting the run.
- A task can be **split** between two runners: two agents, or an AI and a macro.

## Choosing a model per task

Tasks are not equally hard, and paying model prices for clerical work is how budgets
disappear. Each task is classified — programmatic, linear, critical thinking, opaque — and
that classification drives which model is suggested.

Because every run reports what it actually used, the suggestion improves: anticipated cost,
time and tokens sit next to the running total, per task and for the whole run.

## Macros save the most

Anything that can be written as a repetitive macro should be. The macro suitability review
flags tasks that never need judgement; the AI writes the macro the first time and is skipped
on every run after that. Those tasks then cost nothing, which is why they are shown in a
different colour on the map.

Macros are shareable in their own right — an approved macro goes in the macro library.
